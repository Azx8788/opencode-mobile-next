# APK size: where the bytes are and what the next release changes

Measured 2026-10-16 on the published v1.4.0+54 APK (105,024,978 bytes, about
100.2 MiB) and on release builds made on the build server from this branch.
The file is a universal APK: it holds the native libraries for three
processor types, and a phone only ever uses one set.

## What is in the 100 MiB (v1.4.0+54, compressed size in the APK)

| Part | MiB | Note |
|---|---|---|
| lib/x86_64 | 34.6 | emulators and a few Chromebooks only |
| lib/arm64-v8a | 32.8 | nearly every current phone |
| lib/armeabi-v7a | 28.5 | 32-bit phones (cannot run the on-phone setup) |
| classes.dex | 1.7 | R8 already on |
| assets (aiteam manifests, agents, licenses, ML Kit barcode models) | 1.2 | |
| fonts (Geist x4, Phosphor) | 0.4 | already small; CupertinoIcons 0.1 |
| resources | 0.7 | |

Inside one ABI (arm64-v8a, compressed MiB): libapp.so (Dart code) 11.9,
libonnxruntime.so 7.3 (voice), libflutter.so 6.4, libaiteam_engine.so 2.4,
libbarhopper_v3.so 2.0 (QR scanner), libsherpa-onnx-c-api.so 1.8 (voice),
libaiteam_boundary_probe.so 0.5, everything else under 0.5 in total.
No voice models, proot root file system or other large optional assets are
bundled: those download on demand already. The one thing a phone does not
need is the two other processor types, which are 63 MiB of the 100.

## Changes and measured savings

Sizes are from real release builds on the build server (numbers 2360 and
2361), then per-ABI files derived from them with the new script. "Universal"
is the file Shorebird releases; build 2360 is this branch without symbol
stripping, 2361 with it.

| Build | Universal | arm64-v8a only | armeabi-v7a only |
|---|---|---|---|
| v1.4.0+54 as published | 105.0 MB (100.2 MiB) | 38.8 MB (37.0 MiB) | 34.4 MB |
| 2360, no flag | 101.7 MB | 37.8 MB | 33.3 MB |
| 2361, `--split-debug-info` | 95.5 MB | 35.8 MB | 31.1 MB |

1. **Publish one APK per processor type next to the universal one.** An
   arm64 phone downloads 35.8 MB instead of 105 MB: **69.2 MB less (-66%)**.
   A 32-bit phone downloads 31.1 MB. Users lose nothing: a phone runs
   exactly one set of libraries, and the universal APK stays on the release
   page for x86_64 devices and anyone unsure. Risk: low. The per-ABI files are
   the universal APK with the other `lib/<abi>/` folders deleted, then
   re-aligned and re-signed with the same release key
   (`tool/release/split_apk_by_abi.py`). Every kept file is byte-identical
   (checked on all 666 entries), including the matching libapp.so that
   Shorebird registers, so patches still apply. Same package, same
   versionCode, same signer: they update each other.
2. **`--split-debug-info=build/symbols` on Shorebird release and patch.**
   Moves Dart symbol tables out of libapp.so: libapp.so 11.3 -> 9.4 MiB per
   ABI; universal 101.7 -> 95.5 MB (-6.2 MB), arm64 file 37.8 -> 35.8 MB
   (-2.0 MB). Users lose nothing. Cost: Dart stack traces from this build are
   unreadable until symbolized with the saved `build/symbols` files
   (`flutter symbolize -d build/symbols -i trace.txt`); CI now uploads them
   per release. Does not obfuscate names.

Not done, with reasons:

- **Drop x86_64 from the universal APK.** Would save 34.6 MiB there, but the
  emulator QA path installs the universal build and x86_64 Chromebooks would
  lose the app. With change 1 it is no longer needed for download size.
- **Drop 32-bit from the product.** Not needed any more with change 1. The
  connect-to-a-computer path works on 32-bit phones (only the on-phone setup
  needs 64-bit, per the README), so removing it would lose real users.
- **Voice libraries (libonnxruntime + sherpa-onnx, 9.3 MiB per ABI).** They
  are the engine, not models. Moving them out needs an on-demand code
  download, which a sideloaded APK cannot do without a feature-delivery
  channel. Owner decision if voice should become an optional download.
- **QR scanner (libbarhopper + three ML Kit models, 3.0 MiB per ABI).**
  Replacing the scanner package with one that uses a smaller decoder is a
  product change; not attempted.
- **Fonts, images, R8/resource shrinking.** Already about 0.4 MiB of fonts
  and R8 is on; nothing material left. CupertinoIcons.ttf (0.1 MiB) is the
  only candidate and not worth a change.

## What the next release must do differently

- Nothing changes in how you start it: tag push runs
  `.github/workflows/android-release.yml`, or `scripts/release.sh sideload`.
  The Shorebird release is still the universal APK (`--artifact apk`).
- The workflow now also builds `opencode-mobile-<version>-arm64-v8a.apk` and
  `-armeabi-v7a.apk`, checks their signer, versionCode and ABI, and attaches
  them with the universal file; `SHA256SUMS` lists all three.
- Release builds pass `--split-debug-info=build/symbols`. `scripts/release.sh`
  applies the same flag to a patch only for releases with build number 55 or
  higher (`SPLIT_DEBUG_INFO_FROM_BUILD`): a patch must be built the way its
  release was, and v1.4.0+54 was built without it. Keep the uploaded
  `opencode-mobile-symbols-*` artifact of each release.
- `scripts/release.sh sideload` (local) only produces the universal APK; run
  `tool/release/split_apk_by_abi.py` by hand (needs `OC_KS`, `OC_KS_ALIAS`,
  `OC_KS_PASS`, `OC_KEY_PASS` in the environment) if you publish from there.
- README and website download links should point to the `-arm64-v8a.apk` file
  with one line for 32-bit phones (`-armeabi-v7a.apk`) and the universal
  file. This is a wording change at release time; it is not made in this
  branch because the current links point at v1.4.0+54, which has only the
  universal file.
- `check_apk_size.py` still compares the universal APK with the previous
  universal asset, so the 5 MiB growth gate keeps working. A gate on the
  arm64 file would be a sensible addition after the first release with the
  new files.
